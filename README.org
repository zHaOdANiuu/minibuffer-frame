* minibuffer-frame

Show the fido minibuffer in a floating child frame centered on the
parent frame.  The frame grows with wrapped input and completion
candidates, and handles recursive minibuffers.

** Installation

#+begin_src emacs-lisp
(use-package minibuffer-frame
  :vc (:url "https://github.com/zHaOdANiuu/minibuffer-frame" :rev :newest)
  :init (minibuffer-frame-mode 1))
#+end_src

** Customization

=M-x customize-group RET minibuffer-frame RET=

| Variable                    | Default | Description                            |
|-----------------------------+---------+----------------------------------------|
| minibuffer-frame-width      | 0.5     | Frame width (fraction of parent)       |
| minibuffer-frame-top        | 0.3     | Frame top offset (fraction of parent)  |
| minibuffer-frame-max-height | 10      | Maximum frame height in lines          |

** How It Works

- =minibuffer-setup-hook= moves the minibuffer into the child frame.
- The frame height is recomputed on every content change: long input
  wraps at the frame width and the frame grows to fit, up to
  =minibuffer-frame-max-height=; it shrinks again when input shortens.
- Recursive minibuffers reuse the same frame; the frame is hidden and
  focus returns to the exact frame and window selected before the outermost
  minibuffer exits.  If Emacs loses external focus while the minibuffer is
  active, the child frame is hidden and shown again without taking focus.
- An advice on =max-mini-window-lines= lets icomplete lay out its
  candidates inside the child frame.
