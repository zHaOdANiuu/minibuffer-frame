* minibuffer-frame

Show the Fido/icomplete minibuffer in a child frame centered on the
parent frame, sized to fit the completion candidates, and reused
across recursive minibuffers.

** Installation

#+begin_src emacs-lisp
(use-package minibuffer-frame
  :vc (:url "https://github.com/zHaOdANiuu/minibuffer-frame" :rev :newest)
  :init (minibuffer-frame-mode 1))
#+end_src

** Customization

=M-x customize-group RET minibuffer-frame RET=

| Variable               | Default | Description                           |
|------------------------+---------+---------------------------------------|
| minibuffer-frame-width | 0.5     | Frame width (fraction of parent)      |
| minibuffer-frame-top   | 0.3     | Frame top offset (fraction of parent) |

The number of candidate lines icomplete shows inside the frame is
bounded by the built-in =completions-max-height= (one line when it is
unset).

** How It Works

- =minibuffer-setup-hook= creates the child frame on demand, centered
  on the parent at =minibuffer-frame-top=, and for the outermost
  minibuffer shows and focuses it.
- An advice on =icomplete-exhibit= sizes the frame to the completion
  candidates; an advice on =max-mini-window-lines= lets icomplete lay
  those candidates out inside the child frame.
- Recursive minibuffers reuse the same frame without stealing focus;
  it is hidden again when the outermost minibuffer exits.
- =after-focus-change-function= returns focus to the child frame while
  the minibuffer is active, and an advice on =other-window= lets you
  leave the minibuffer and cycle back into it.
